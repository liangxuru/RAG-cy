pipeline.py 逻辑梳理

企业知识库 RAG 项目中数据预处理与问答编排的主入口：路径配置、PDF/Markdown 处理、向量库构建与批量/单条问答。

1. 文件角色概览

pipeline.py 将「数据目录 + 运行配置」封装为 Pipeline 类，对外提供从 PDF/Markdown 到分块、向量库、再到问题批处理或单问推理的一组方法。模块级常量 PROJECT_ROOT 指向仓库根目录；预置多组 RunConfig（如 max_config）供脚本或 UI 选用。

5. 初始化与辅助逻辑

构造 Pipeline(root_path, …, run_config)

  • _initialize_paths：用 run_config.use_serialized_tables、config_suffix 生成 PipelineConfig。
  • _convert_json_to_csv_if_needed：若存在 subset.json 且无 subset.csv，则读 JSON 写 CSV，供后续模块使用公司元数据。

_get_next_available_filename

批量写答案时避免覆盖：若 answers*.json 已存在，则依次尝试 answers_01.json、answers_02.json …

6. RunConfig 主要字段

字段含义
parent_document_retrieval是否启用父文档检索（大块上下文）
llm_reranking检索结果是否经 LLM 重排
top_n_retrieval检索返回条数
parallel_requests批处理并发（注释中提示需控制以免触发 QPM 限流）
api_provider / answering_model默认 dashscope + qwen-turbo-latest
submission_file / pipeline_details交给 QuestionsProcessor.process_all_questions 控制输出格式与说明字段
config_suffix拼入答案文件名等，区分不同实验配置

7. 预置配置字典

  • preprocess_configs：ser_tab / no_ser_tab，仅切换 use_serialized_tables。
  • base_config：较高 parallel_requests，带 config_suffix="_base"。
  • parent_document_retrieval_config：开启 PDR，GPT-4o，后缀 _pdr。
  • max_config：PDR + 重排 + Qwen Turbo，后缀 _qwen_turbo（Streamlit 与 __main__ 示例常用）。
  • configs：将 base、pdr、max 映射到上述对象。
